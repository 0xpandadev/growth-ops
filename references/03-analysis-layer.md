# Analysis Layer

The analysis layer turns evidence into a decision.

## Core Logic

1. Frame the decision.
2. Build a simple issue tree.
3. Generate 2-4 hypotheses.
4. Score or compare only decision-relevant options.
5. Explain the mechanism.
6. Identify falsifiers.
7. Translate to next actions.

## Mechanism-First Thinking

Avoid "this is promising" unless the mechanism is clear.

Use this chain:

```text
Signal -> Mechanism -> Business implication -> Test -> Decision
```

Examples:

- Job posts for RevOps + CRM migration -> workflow pain and budget exist -> sell implementation package -> test with 10 target accounts -> prioritize accounts with explicit migration trigger.
- Falling gross margin + high owner dependency -> unpriced custom work and weak process -> standardize offers and stop loss-making jobs -> test margin by customer/order -> 90-day operator plan.

## Scoring Rules

Use 1-5 or 0-100 scores only when they clarify tradeoffs. Always include reason and evidence.

Good scoring dimensions:

- pain urgency
- budget / ability to pay
- timing trigger
- reachability
- fit with user's strengths
- execution complexity
- downside / risk
- evidence strength

Never hide weak evidence behind precise-looking numbers.

## Synthesis Rules

Strong synthesis:

- compresses many facts into a decision-relevant mechanism
- states what matters and what does not
- gives a practical next action
- identifies what would change the conclusion

Weak synthesis:

- summarizes everything equally
- lists trends
- uses consulting vocabulary without evidence
- gives no owner, test, or KPI

## Decision Outputs

Choose one:

- `Go / no-go / wait`
- `Prioritize A over B`
- `Test first, then decide`
- `Fix operations before growth`
- `Create asset, then validate demand`
- `Stop doing X`
- `Escalate to professional/legal/financial specialist`
