# Quality Gates

Run these before finalizing important outputs.

## Evidence Gate

- What is fact?
- What is inference?
- What is assumption?
- What is unknown?
- Are current claims verified when needed?

## Input Understanding Gate

- Did we identify the real decision or job-to-be-done?
- Did we convert messy input into entities, claims, numbers, constraints, and unknowns?
- Did we preserve what the user actually cares about instead of forcing a generic framework?
- Did we avoid a mere summary?

## Mechanism Gate

- Why would this happen?
- What is the buyer, workflow, budget, or cash mechanism?
- What changed recently?
- What bottleneck or constraint matters most?

## Decision Gate

- What decision does the user need to make?
- What option is recommended?
- What is the next action?
- What is the cost of being wrong?

## Falsification Gate

- What signal would prove this wrong?
- What test can be run within days or weeks?
- What data should be tracked?

## Small-Business Practicality Gate

- Can a solo operator or small team do this?
- Is the action too enterprise-heavy?
- Does it require tools, data, money, or staffing the user may not have?
- Is there a cheaper manual-first version?

## Karpathy-Style Scope Gate

Use this when the output risks becoming too big:

- What is the simplest working version?
- What can be removed?
- What assumption is most uncertain?
- What would success look like in one week?
- What would a competent skeptic say?

## Asset Meaning Gate

For slides, dashboards, charts, icons, and diagrams:

- Does every visual encode meaning?
- Can the icon replace or clarify text?
- Is the chart the right chart for the data?
- Is the structure easier to understand than prose?
- Remove decorative-only visuals.

## Method Substance Gate

- Did each named source family change the output?
- Did it create a diagnostic question, output field, metric, or falsifier?
- Is any external method present only as a name? If yes, remove it or operationalize it.
