# Skill Blueprint

Use this when the user wants to turn repeated work into a skill.

## Skill Candidate Test

A task deserves a skill when:

- the user repeats it often
- the workflow has domain-specific steps
- there are recurring templates or references
- quality depends on remembered rules
- output can be tested

## Blueprint

1. Skill name
2. Trigger description
3. User examples
4. Workflow
5. Reference files
6. Templates/assets
7. Quality gates
8. Non-goals
9. Handoff to other skills
10. Test prompts

## Growth Ops Skill Map

If creating new skills from Growth Ops work, keep them narrow:

- market-radar skill
- account-scorecard skill
- turnaround-memo skill
- ops-ontology skill
- content-asset-factory skill

Avoid creating too many child skills too early. Start with references inside `growth-ops`; split later only when a workflow becomes frequent and stable.
