# Growth Ops

**Growth Ops は、事業機会を見つけ、意思決定を整理し、雑多な情報を実際に使えるビジネス成果物へ変換するためのオペレーティング・インテリジェンス Skill です。**

[English](../README.md) | [日本語](./README.ja.md) | [中文](./README.zh-CN.md)

Growth Ops は、創業者、一人会社、中小企業、コンサルタント、投資家、新規事業担当、AI活用を進めたいオペレーターのために作られています。

単なる要約ではありません。URL、メモ、会社リスト、市場テーマ、顧客リスト、事業課題、古い会社の再生相談、AI業務化アイデアなどを読み取り、次のようなアウトプットに変換します。

- 市場レーダー
- 事業機会カード
- アカウント / リードスコアリング
- 中小企業の経営診断メモ
- ターンアラウンド計画
- 提案書ブリーフ
- HTMLダッシュボード設計
- note / 記事 / SNS のコンテンツ計画
- スライド構成
- 再利用できる Skill 設計書

中心にある考え方はシンプルです。

```text
情報を要約するだけでは足りない。
事業状況を理解し、重要なシグナルを抜き出し、何を判断すべきかを明確にし、次の行動まで落とす。
```

## 何が違うのか

多くの AI 出力は、きれいにまとまっているように見えて、実際には使えないことがあります。

- トレンドを並べるだけ
- フレームワーク名を出すだけ
- 市場規模を語るだけ
- きれいな表を作るだけ
- 「AIで効率化できます」と言うだけ

Growth Ops は、そこで止まりません。

- 本当の意思決定は何か
- 事実、推論、仮定、不明点は何か
- どのシグナルが本当に意味を持つのか
- なぜその機会や問題が起きているのか
- 今週何を検証すべきか
- 何が起きたら仮説を捨てるべきか
- 最終的にどんな成果物があると動けるのか

ここまで落とすことを目指します。

## 3つの内部レーン

ユーザーがモード名を覚える必要はありません。普通に依頼すれば、内部で自動的に振り分けます。

```text
growth-ops
  radar    = 外を見る: 市場、テーマ、競合、営業先、提携先、弱いシグナル
  operator = 中を見る: 事業モデル、現金、業務、承継、再生、近代化
  assets   = 形にする: メモ、提案書、スライド、HTML、記事、Skill設計
```

## Radar: 外を見る

Radar は、市場や外部シグナルを見るためのレーンです。

使う場面:

- この市場テーマは本当に有望か
- ただの流行なのか、実需があるのか
- どの会社、顧客、提携先、買収候補を見るべきか
- どのシグナルが勢い、タイミング、予算、痛みを示しているのか
- その領域は成熟前か、過熱中か、実装フェーズか

参考にする考え方:

- Exa 風の semantic discovery / Websets
- YC Essential Startup Advice / Requests for Startups
- Sequoia PMF
- a16z のカテゴリマップ / AI / marketplace 的視点
- NFX Network Effects
- Reforge Growth Loops
- Gartner Hype Cycle
- Porter Five Forces
- CB Insights Mosaic / Private Company Health
- 6sense の fit / intent / buying stage
- Clay のカスタムスコアリング
- SignalFire / Harmonic / PitchBook / Dealroom 的な市場シグナル

ただし、有料データベースを再現するものではありません。公開情報、ユーザー提供データ、ローカルファイル、利用可能なリサーチ手段から、同じ「見方」を使って判断材料を作ります。

## Operator: 中を見る

Operator は、事業の中身を見て、現実的な改善・再生・運用に落とすレーンです。

使う場面:

- 古い中小企業をどう近代化するか
- 事業承継した会社をどう立て直すか
- 倒産しそうな会社をどう見るか
- どの商品、顧客、業務が利益を生んでいるか
- キャッシュ、負債、人、業務、顧客のどこから直すべきか
- AIを入れる前に、どの業務を標準化すべきか

抽象的な戦略ではなく、次のような現実に落とします。

- 誰がやるか
- いつまでにやるか
- どのデータを見るか
- 現金、顧客、業務、リスクに何が変わるか
- 今週テストできることは何か

## Assets: 形にする

Assets は、分析結果を人に見せたり、実務で使ったりできる形に変換するレーンです。

作れるもの:

- 意思決定メモ
- 市場レーダー
- アカウントスコアカード
- 提案書ブリーフ
- note記事構成
- スライド構成
- HTMLダッシュボード仕様
- Skill設計書

Growth Ops は、チャット内で終わる分析ではなく、外に持ち出せる成果物を作ることを重視します。

## Growth Board: 事業判断のためのGUI

Growth Ops は、分析結果を **Growth Board** というGUI / knowledge UI に変換できます。

これは普通のKPIダッシュボードではありません。情報がどう判断に変わるかを見せる画面です。

```text
signal -> interpretation -> decision -> action
```

ユーザーが細かい画面名を覚える必要はありません。

```text
[$growth-ops]
この情報をGrowth Board化して。
<メモ、会社リスト、市場テーマ、雑データ、業務フロー>
```

と言えば、Growth Ops が内部で向いている画面を選びます。

- **Auto Board**: 目的が曖昧な雑データをまず整理する
- **Signal Board**: 市場テーマ、弱いシグナル、ニュース、会社の動きを見る
- **Score Board**: 営業先、提携先、投資候補、買収候補、アイデアを順位付けする
- **Map Board**: 会社、顧客、商品、業務、人物、資金、資料の関係を見る
- **Scenario Board**: 価格変更、AI導入、再生、採用、資金繰りなどの仮説を見る
- **Action Board**: 誰が、何を、いつ、どの条件で動くかに落とす

見た目は、普通のSaaSダッシュボードではなく、Palantir的な object/state/action、CB Insights的な signal stack、6sense/Clay的なスコアリング、Neo4j的な関係グラフ、Runway/Pigment的なシナリオ、incident.io/PagerDuty的なアクション管理、Tufte/Few的な情報密度を参考にした、クールで高密度な事業操作画面を目指します。

Codex では、こう呼び出します。

```text

<URL / メモ / 会社リスト / 市場テーマ / 事業課題>
```

もっと短くても大丈夫です。

```text
[$growth-ops]
これを意思決定できる形にして。
```

## 依頼例

### 市場テーマを見たい

```text
[$growth-ops]
このテーマが本当に有望か見て。
なぜ今なのか、誰が困っているのか、競合は誰か、何を検証すべきかまで出して。
```

### 営業先や提携先をスコアしたい

```text
[$growth-ops]
この会社リストを優先順位付けして。
ICP適合、痛み、タイミング、intent、予算、接触しやすさ、次アクションでスコアして。
```

### 古い会社を立て直したい

```text
[$growth-ops]
この古い中小企業を引き継ぐ前提で、どこから立て直すべきか見て。
現金、利益、顧客、業務、人、AI活用、90日計画で整理して。
```

### AI業務化を考えたい

```text
[$growth-ops]
この業務はAIエージェント化すべきか、それとも単純なworkflowで十分か見て。
必要なデータ、ツール、評価、ガードレール、人間の確認ポイントまで設計して。
```

### 記事・提案書・スライドにしたい

```text
[$growth-ops]
このURLとメモをもとに、note記事案、提案書ブリーフ、スライド構成、HTMLダッシュボード案にして。
```

## 標準アウトプット

通常は次の形で返します。

1. 結論
2. 何を判断すべきか
3. 事実 / 推論 / 仮定 / 不明点
4. メカニズム
5. 選択肢またはスコア
6. 推奨アクション
7. 間違っている可能性 / 検証ポイント

## 向いている人

- 一人会社で、調査・営業・記事・提案・事業開発を全部回している人
- 中小企業を経営していて、現実的な打ち手が欲しい人
- 古い会社を引き継ぐ、買う、再生する、近代化する可能性がある人
- 新規事業やAI活用のアイデアを、実行可能な形にしたい人
- 投資テーマや会社リストを、表面的ではなくシグナルで見たい人
- コンサル資料や提案書の前段として、考えを深く整理したい人

## これは何ではないか

Growth Ops は、CB Insights、PitchBook、Dealroom、6sense、Clay、SignalFire、Harmonic、Gartner、McKinsey、BCG、Bain、Palantir、YC、Sequoia などの有料・非公開データを持っているふりはしません。

使うのは、公開されている考え方、ユーザーが提供した情報、ローカルファイル、利用可能なリサーチ手段です。

つまり、秘密のデータベースではなく、**見方・分解・判断・出力のための Skill** です。

## なぜ作ったか

小さいチームや一人会社に必要なのは、きれいな戦略ごっこではありません。

必要なのは、散らかった情報から重要なことを見つけ、何をすべきか決め、すぐ使える形にすることです。

```text
雑な情報 -> 構造化された判断 -> 次の行動 -> 使える成果物
```

Growth Ops は、この流れを一つの Skill として扱うためのものです。
